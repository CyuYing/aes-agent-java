数据库作业评分标准与数据库原理知识库

适用范围：
本标准用于数据库课程 SQL 作业批改，覆盖表结构设计、约束、增删改查、连接查询、聚合统计、子查询、事务与基础性能优化。批改时应结合题目要求、学生 SQL 和系统执行证据。

一、题意与执行结果正确性（35 分）
1. SQL 能在给定初始化脚本和测试数据上成功执行，是基本前提。
2. SELECT 查询应返回题目要求的字段、行范围、排序和聚合结果。
3. INSERT/UPDATE/DELETE 应影响正确数据，不应误改无关记录。
4. DDL 题应创建正确表、字段类型、主键、外键、唯一约束和非空约束。
5. 语法错误、表名列名错误、结果为空但题目预期非空，应在本维度显著扣分。

二、SQL 规范与可读性（15 分）
1. 关键字建议大写，表名和列名保持一致风格。
2. 多表查询应使用明确的 JOIN ... ON，而不是难以维护的隐式连接。
3. 复杂条件应合理换行和缩进，避免一行堆叠过长。
4. 字段应显式列出，除调试场景外不建议滥用 SELECT *。
5. 别名应有语义，例如 student_count、avg_score，而不是 a、b、c。

三、关系建模与查询逻辑（25 分）
1. 表设计应符合实体、属性、联系的关系模型思想。
2. 主键应能唯一标识元组，外键应表达表之间的参照关系。
3. 连接条件必须完整，避免笛卡尔积。
4. 聚合查询应正确使用 GROUP BY、HAVING 和聚合函数。
5. 子查询或 EXISTS 应表达清晰逻辑，避免与题意相反的 IN/NOT IN 误用。

四、性能与索引意识（15 分）
1. WHERE、JOIN、ORDER BY 常用列可考虑索引。
2. 避免在索引列上包裹函数导致索引失效，例如 DATE(create_time)。
3. 大表查询应避免无条件全表扫描。
4. 只返回必要列和必要行，合理使用 LIMIT。
5. 聚合和排序应理解执行成本，必要时先过滤再聚合。

五、安全性与可维护性（10 分）
1. 不应出现拼接用户输入导致 SQL 注入风险的写法。
2. 删除和更新语句必须包含明确 WHERE 条件，除非题目明确要求全表操作。
3. 不应使用危险数据库函数、外部文件读取或脚本执行语句。
4. 事务题应理解 ACID，涉及多步写操作时应考虑提交和回滚。
5. SQL 应便于复查和迁移，避免依赖无关环境状态。

执行证据使用原则：
系统会使用 H2 内存数据库的 MySQL 兼容模式执行 SQL。若失败原因是明显语法或逻辑错误，应据此扣分；若是 H2 与 MySQL 方言差异，应在评语中说明并酌情处理。
