Java 作业评分标准与 Java 原理知识库（Java 17）

适用范围：
本标准用于 Java 程序设计课程的 Word 作业批改，尤其适用于包含“题目要求 + 学生代码”的作业文档。评分时应先判断代码是否满足题意，再评价语法、面向对象设计、运行逻辑和可维护性。

一、题意符合性（30 分）
1. 完整实现题目要求的类、变量、方法、构造方法、测试类与调用流程，给 20-24 分。
2. 对题目中明确要求的重载、访问修饰符、静态成员、实例成员、输入输出、边界条件均有覆盖，给 25-30 分。
3. 缺少核心类、核心方法或测试入口时，应在本维度显著扣分。
4. 只写了片段但未形成可运行结构，最高不超过 18 分。

二、Java 语法与代码规范（20 分）
1. 类名使用 UpperCamelCase，变量和方法使用 lowerCamelCase，常量使用 UPPER_SNAKE_CASE。
2. public 类名应与文件名一致；同一文件中多个顶层类时，只能有一个 public 类。
3. 缩进、空格、括号位置应统一；Word 转换产生的多余空行不应单独扣分。
4. 注释应解释关键设计意图，不应只重复代码表面含义。
5. 存在明显编译错误、缺少分号、括号不匹配或类型错误，应按严重程度扣分。

三、逻辑正确性（20 分）
1. 构造方法应正确初始化对象状态，避免遗漏字段赋值。
2. 实例方法应通过对象调用并访问实例变量；类方法应通过类名调用并访问静态变量。
3. 方法重载必须满足参数列表不同，不能只改变返回值。
4. 测试类 main 方法应能覆盖题目要求的关键路径。
5. 如果输出内容与题目要求不一致，或调用顺序导致结果错误，应扣分。

四、性能与资源使用（15 分）
1. 普通基础作业以简洁、直接、无冗余为主，不要求过度优化。
2. 避免无意义的重复对象创建、重复循环、硬编码大量相同逻辑。
3. 涉及集合、数组、字符串拼接时，应关注复杂度和可读性。
4. 不应为了展示语法而引入过重框架或无关依赖。

五、可维护性与面向对象设计（15 分）
1. 封装：实例变量优先 private，通过构造方法、getter/setter 或业务方法访问。
2. 静态成员：只用于类级共享状态，不能滥用 static 逃避对象建模。
3. 职责：实体类负责状态与行为，测试类负责创建对象和调用方法。
4. 扩展性：重载方法应有清晰语义，不应形成重复且难维护的代码。
5. 可读性：命名应贴合领域，避免 a、b、test1 等无意义名称。

评分输出要求：
批改结果应包含总体评价、分维度得分、具体问题清单、参考范例对比和改进建议。指出问题时尽量引用具体代码片段或方法名。若学生代码满足题意但有轻微风格问题，应避免过度扣分。
